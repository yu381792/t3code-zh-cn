# 中文版每日更新

本 fork 的「中文版每日更新」流程在北京时间每天 07:17 读取官方 `main`，尝试合并，运行中文审计、相关菜单测试与桌面类型检查，然后在 GitHub 的 Mac arm64 机器上构建。源码未变时跳过。任何合并冲突或检查失败都会停止；已经发布的版本继续保留，失败位置见运行记录。修复后可手动运行同一流程。

此流程只在公开仓库运行，固定使用免费的标准 `macos-15` 机器，不使用付费的大型机器、外部构建服务或 GitHub 会员功能。仓库改为私有时自动跳过，避免进入私有仓库的计费口径。安装包放在 GitHub Releases，不额外保存大型 Actions 构建产物。

流程只发布本仓库的 Mac arm64 DMG、ZIP、校验值和构建来源，不部署官方网站、移动客户端或 npm 包。新代码通过构建后才正常推送到本 fork 的 `main`；并行修改导致推送被拒绝时停止，不强推。合并后的源码会保存在 GitHub，本机下次用 `git pull --ff-only fork main` 同步。

`.github/fork-upstream.txt` 记录上次已合并的官方提交。每天由 Git 根据该快照、fork 当前源码、官方新源码做三方合并，将结果提交到 fork。官方发布工作流依赖其专用机器与凭据，因此保留本仓库自己的 `.github/workflows`；自动提交也不会导入修改这些工作流的官方提交历史，不需要额外个人令牌或 SSH 密钥。若官方改写历史或出现冲突，流程停止。

目前未配置 Apple 开发者签名证书。自动构建和发布可以工作，但 Mac 原生自动安装需要合适的签名；临时签名版只发布下载安装包，不上传自动安装清单。应用原有更新源已经指向本仓库。取得签名条件后，配置官方发布流程所需的 `CSC_LINK`、`CSC_KEY_PASSWORD`、`APPLE_API_KEY`、`APPLE_API_KEY_ID`、`APPLE_API_ISSUER`、`MACOS_PROVISIONING_PROFILE` 和仓库变量 `APPLE_TEAM_ID`，本流程会使用已有签名及公证脚本。首次迁移到正式签名版需手动安装，再做实际自动更新验收。

手动运行时保持「合并官方 main」开启即可。关闭它可仅重建当前中文版，用于维护修复或验证发布流程；这类版本不会宣称已跟上最新官方源码。没有特殊需要不勾选强制重新发布。

GitHub 运行失败可由账户原有 Actions 通知送达，不另外创建监控或自动发消息。项目的其他继承工作流依赖官方基础设施，本 fork 不启用它们。
